Problem Statement

Hypertension is a silent epidemic

Existing blood pressure monitors provide raw numbers without context. Patients don't understand what their readings mean, can't identify patterns, and don't know which lifestyle factors affect their BP.

  • ✗ No contextual intelligence — devices show numbers, not insights
  • ✗ No trend detection — patients can't see patterns over time
  • ✗ No lifestyle correlation — no link between habits and BP changes
  • ✗ No actionable guidance — patients don't know what to do
1.28B Adults affected globally (WHO)
46% Unaware of their condition
#1 Modifiable risk factor for CVD
Aim of the Study

To develop an AI-powered web application for blood pressure management

This project aims to design and implement a Smart AI Blood Pressure Tracker that goes beyond basic data logging — providing intelligent classification, trend analysis, lifestyle correlation, and personalised health coaching through an accessible web-based interface.

  • 🎯 Transform passive monitoring into active health management through AI-driven insights
  • 🧠 Bridge the gap between raw BP numbers and actionable health intelligence
  • 📱 Enable device integration via Bluetooth Low Energy for seamless data capture
Project Scope
A functional prototype demonstrating AI-assisted BP monitoring — not a certified medical device. The system targets usability, interpretability, and real-time feedback over clinical deployment.
Key Differentiator
Unlike existing apps that act as digital logbooks, this system provides contextual intelligence — explaining why readings changed and what to do about it.

Implementation

The AI engine — three layers of intelligence

🏥
Layer 1: Classification
Maps average systolic/diastolic against ACC/AHA clinical thresholds. Ordered conditionals — severe cases checked first.
if avg_sys ≥ 140 OR avg_dia ≥ 90
  → "Stage 2"
elif avg_sys ≥ 130 OR avg_dia ≥ 80
  → "Stage 1"
elif 120 ≤ sys < 130 AND dia < 80
  → "Elevated"
📉
Layer 2: Trend Detection
Sliding window comparison — average of last 3 readings vs all previous. ±5 mmHg threshold (clinically meaningful).
recent = mean(last_3)
past = mean(all_previous)

if recent > past + 5 → "Rising"
if recent < past - 5 → "Falling"
else → "Stable"
🔗
Layer 3: Correlations
Groups readings by lifestyle tags ("Stressed", "Salty Meal"). Flags tags with ≥10 mmHg deviation from overall average.
for tag with ≥2 occurrences:
  diff = tag_avg - overall_avg
  if diff > 10:
    "BP higher with tag"
  if diff < -10:
    "BP lower with tag"

Challenges & Solutions

Problems encountered, lessons learned

⚡ Challenge
BP boundary classification — 120/80 must be Normal, not Elevated. Ordered conditional logic required careful validation.
✓ Solution
Ordered checks matching ACC/AHA priority (Stage 2 first). Comprehensive boundary test cases validating all transition points.
⚡ Challenge
BLE data format — IEEE 11073-20601 SFLOAT uses 4-bit exponent + 12-bit mantissa, not standard IEEE 754 floats.
✓ Solution
Custom parser extracting mantissa/exponent from raw DataView bytes. Tested against known reference values.
⚡ Challenge
Context-aware chat without external APIs — Building useful AI responses without OpenAI/Gemini dependency.
✓ Solution
Keyword-driven, context-injected system. Chat endpoint retrieves user's actual analysis data before branching responses.
⚡ Challenge
CORS blocking — Frontend on port 5173 (Vite) couldn't reach backend on port 8000 (Uvicorn).
✓ Solution
FastAPI CORS middleware configured to whitelist Vite dev server origin. Tested with CORS preflight validation in system tests.
